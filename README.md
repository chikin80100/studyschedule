# StudySchedule — 勉強習慣化・管理アプリ

**公開先: https://chikin80100.github.io/studyschedule/**

学習の **内容・期間・量** を入力すると、1日ごとのタスクを自動で作ってくれるアプリです。
毎日の完了確認、進捗に応じた計画の修正、連続達成記録(ストリーク)まで一通り揃っています。

サーバー不要の静的サイトなので、GitHub Pages にそのまま置けます。

## 主な機能

### 1日ごとのタスクを自動生成
「数学の問題集 300ページを 9/1〜9/30 で終わらせる」と入力するだけで、日別のタスクができます。

### 曜日ごとの配分
曜日ごとに **休養日** にするか、**量の比率(重み)** をいくつにするかを設定できます。
「平日は多め、土日は軽め、日曜は休み」といった現実的な計画が組めます。
プリセット(毎日おなじ / 平日を多め / 休日を多め)も用意しています。

### キッチリ割らず「余白」を持たせる配分
割り切れない量を無理やり均等配分すると、1日 8.33 ページのような扱いにくい数になり、
1日つまずいただけで計画全体が崩れます。このアプリでは2種類の余白を入れます。

1. **予備日** — 期間の末尾を予備日として空けておきます(なし / 10% / 15% / 25%)。
   遅れたときの受け皿になります。
2. **切り上げ** — 1日あたりの量をキリのいい単位(おまかせ / 0.5 / 1 / 5 / 10)に切り上げます。
   端数が消えるうえ、計画が **予定より前倒しで終わる** ので、末尾がさらに空きます。

切り上げた分は最終日で総量ぴったりに切り詰めるため、**計画量の合計は入力した総量と必ず一致** します。

### 毎日の完了確認と、進捗に応じた計画の修正
- 過ぎた日で完了になっていないタスクを「未確認」としてまとめて表示します(直近2週間ぶん)。
  「すべてできた」「できなかった(確認済みにする)」でまとめて記録でき、確認した日は次から出てきません。
- 遅れているプランは警告が出て、**まだ終わっていない量を今日以降に配り直す** ことができます。
  残りの日数に合わせて1日の量が再計算されます。過去の日は「その日にやった量」で確定するので、
  配り直したあとに古い遅れが残り続けることはありません。できなかった日の記録はそのまま残るため、
  連続達成記録の履歴が書き換わることもありません。
- 今日の分をすでに終えている場合は、翌日から配り直します(今日に二重で割り当てません)。
- 残り期間に学習日が無いときは、配り直さずにその旨を伝えます。
- プラン詳細からはいつでも手動で配り直せます。

### 連続達成記録(ストリーク)
その日の計画量をすべて終えた日が「達成」です。現在の連続日数と最長記録、直近3週間のカレンダーを表示します。
- **休養日と予備日は連続記録を途切れさせません**(日数にも数えません)。
- 今日はまだ取り組み中とみなすので、未達成でも記録は途切れません。
- プランが1つも動いていない空白期間があると、そこで連続は途切れます。
- 複数のプランがある日は、そのすべてを終えて初めて「達成」になります。

### データの持ち出し
データはブラウザの localStorage に保存されます。設定画面から JSON で書き出し / 読み込みができるので、
別の端末やブラウザへ移せます。読み込みは形式を検証するので、無関係な JSON で今のデータが消えることはありません。
保存に失敗した場合(容量オーバーやプライベートモード)は画面上で知らせます。

## ローカルで動かす

```bash
npm install
npm run dev      # http://localhost:5173/studyschedule/
```

その他のコマンド:

```bash
npm test         # 単体テスト (123件、ランダム入力での不変条件チェックを含む)
npm run test:tz  # 主要なタイムゾーンでテストを回す
npm run build    # 型チェック + 本番ビルド (dist/)
npm run preview  # ビルド結果を確認
```

## GitHub Pages で公開する

`.github/workflows/deploy.yml` が用意してあり、`main` ブランチに push すると自動でビルド・デプロイされます。
ワークフローの `actions/configure-pages` に `enablement: true` を指定しているので、
Pages が未設定でも初回実行時に有効化されます。

うまく有効化されなかった場合は、リポジトリの **Settings** → **Pages** →
**Build and deployment** の **Source** を **GitHub Actions** に変更してから、
Actions タブで `Deploy to GitHub Pages` を再実行してください。

公開先は `https://<ユーザー名>.github.io/studyschedule/` です。

> リポジトリ名を `studyschedule` 以外に変える場合は、`vite.config.ts` の `base` も
> `'/<新しいリポジトリ名>/'` に合わせて変更してください。

## 構成

```
src/
  lib/taskGenerator.ts  期間・量・曜日設定 → 日別タスク(予備日と切り上げの中核)
  lib/reschedule.ts     進捗に応じて残りを配り直す
  lib/progress.ts       連続達成記録・遅れ/貯金の集計・毎日の確認対象の抽出
  lib/amount.ts         量の丸めと、誤差を積まない合算
  lib/date.ts           'YYYY-MM-DD' 文字列ベースの日付ユーティリティ
  storage.ts            localStorage への保存・読み込み・書き出し
  hooks/usePlans.ts     プランとタスクの CRUD
  pages/                今日 / プラン一覧 / 作成・編集 / 詳細 / 設定
  components/           タスク行・進捗バー・曜日エディタ・ストリークカード
```

技術構成: React 19 / TypeScript / Vite / Tailwind CSS / Vitest。バックエンドはありません。

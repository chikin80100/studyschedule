# StudySchedule — 勉強習慣化・管理アプリ

**公開先: https://chikin80100.github.io/studyschedule/**

学習の **内容・期間・量** を入力すると、1日ごとのタスクを自動で作ってくれるアプリです。
毎日の完了確認、進捗に応じた計画の修正、連続達成記録(ストリーク)まで一通り揃っています。

本体はサーバー不要の静的サイトなので、GitHub Pages にそのまま置けます。
複数の端末で同じデータを使いたい場合だけ、小さな同期サーバーを別途用意できます(任意)。

## 主な機能

### 1日ごとのタスクを自動生成
「数学の問題集 300ページを 9/1〜9/30 で終わらせる」と入力するだけで、日別のタスクができます。

### 曜日ごとの配分
曜日ごとに **休養日** にするか、**量の比率(重み)** をいくつにするかを設定できます。
「平日は多め、土日は軽め、日曜は休み」といった現実的な計画が組めます。
プリセット(毎日おなじ / 平日を多め / 休日を多め)も用意しています。

### キッチリ割らず「余白」を持たせる配分
割り切れない量を無理やり均等配分すると、1日 8.33 ページのような扱いにくい数になり、
1日つまずいただけで計画全体が崩れます。このアプリでは2種類の余白を入れます。

1. **予備日** — 期間の末尾を予備日として空けておきます(なし / 10% / 15% / 25%)。
   遅れたときの受け皿になります。
2. **切り上げ** — 1日あたりの量をキリのいい単位(おまかせ / 0.5 / 1 / 5 / 10)に切り上げます。
   端数が消えるうえ、計画が **予定より前倒しで終わる** ので、末尾がさらに空きます。

切り上げた分は最終日で総量ぴったりに切り詰めるため、**計画量の合計は入力した総量と必ず一致** します。

### 毎日の完了確認と、進捗に応じた計画の修正
- 過ぎた日で完了になっていないタスクを「未確認」としてまとめて表示します(直近2週間ぶん)。
  「すべてできた」「できなかった(確認済みにする)」でまとめて記録でき、確認した日は次から出てきません。
- 遅れているプランは警告が出て、**まだ終わっていない量を今日以降に配り直す** ことができます。
  残りの日数に合わせて1日の量が再計算されます。過去の日は「その日にやった量」で確定するので、
  配り直したあとに古い遅れが残り続けることはありません。できなかった日の記録はそのまま残るため、
  連続達成記録の履歴が書き換わることもありません。
- 今日の分をすでに終えている場合は、翌日から配り直します(今日に二重で割り当てません)。
- 残り期間に学習日が無いときは、配り直さずにその旨を伝えます。
- プラン詳細からはいつでも手動で配り直せます。

### 連続達成記録(ストリーク)
その日の計画量をすべて終えた日が「達成」です。現在の連続日数と最長記録、直近3週間のカレンダーを表示します。
- **休養日と予備日は連続記録を途切れさせません**(日数にも数えません)。
- 今日はまだ取り組み中とみなすので、未達成でも記録は途切れません。
- プランが1つも動いていない空白期間があると、そこで連続は途切れます。
- 複数のプランがある日は、そのすべてを終えて初めて「達成」になります。

### 端末間で同期する (任意)
同期サーバーを用意すると、スマホと PC など複数の端末で同じデータを使えます。
**設定しなければ完全にオフで、これまで通りこの端末だけで完結します。**

- **同期コード方式** — 発行したコードを他の端末で入力するだけ。アカウント登録は不要です。
- **ローカル優先** — 書き込みはこれまで通り手元に保存し、つながったときに後追いで同期します。
  電車の中など通信できない場所でも普通に使えて、オンラインに戻ると自動で反映されます。
- **どちらの記録も消えない** — 「A で今日の分を終え、B で計画を組み直した」ような場合も、
  計画は新しいほう、記録は日ごとに新しいほうを採る形でマージします。
  片方で削除したプランが、もう片方から復活することもありません。

用意のしかたは後述の「同期サーバーを立てる」を参照してください。

> 同期コードはパスワードと同じです。知っている人は誰でもそのデータを読み書きできます。
> 人目に触れるところに貼らないでください。

### データの持ち出し
データはブラウザの localStorage に保存されます。設定画面から JSON で書き出し / 読み込みができるので、
別の端末やブラウザへ移せます。読み込みは形式を検証するので、無関係な JSON で今のデータが消えることはありません。
保存に失敗した場合(容量オーバーやプライベートモード)は画面上で知らせます。

## GitHub Pages で公開する

`.github/workflows/deploy.yml` が用意してあり、`main` ブランチに push すると自動でビルド・デプロイされます。
**最初に一度だけ**、リポジトリ側で2つの設定が必要です(どちらも API から変更できないため手作業です)。

1. **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に変更する
   これが「Deploy from a branch」のままだと、`github-pages` 環境が
   `Branch "main" is not allowed to deploy to github-pages due to environment protection rules.`
   でデプロイジョブを弾きます。
2. **Settings → General → Default branch** を **`main`** にする
   `github-pages` 環境はデフォルトブランチからのデプロイを許可するため、
   `main` をデフォルトにしておく必要があります。

設定後、Actions タブの `Deploy to GitHub Pages` を再実行するか、`main` に何か push すればデプロイされます。

公開先は `https://<ユーザー名>.github.io/studyschedule/` です。

> リポジトリ名を `studyschedule` 以外に変える場合は、`vite.config.ts` の `base` も
> `'/<新しいリポジトリ名>/'` に合わせて変更してください。

## 同期サーバーを立てる

`server/` に Cloudflare Workers + D1 用のコードが入っています。無料枠で足りる規模です。
**この手順はあなたのアカウントでの認証が必要なので、手元のターミナルで実行してください。**

```bash
cd server
npm install

# 1. Cloudflare にログインする (ブラウザが開きます)
npx wrangler login

# 2. D1 データベースを作る
npx wrangler d1 create studyschedule
#    表示された database_id を wrangler.toml の database_id に貼り付ける

# 3. テーブルを作る
npm run db:remote

# 4. 公開する
npm run deploy
```

デプロイすると `https://studyschedule-sync.<サブドメイン>.workers.dev` のような URL が表示されます。
アプリの **設定 → 端末間で同期** でその URL を入力し、**新しいコードを発行** を押してください。
表示されたコードを他の端末でも入力すれば、同期が始まります。

`wrangler.toml` の `ALLOWED_ORIGINS` には、アプリを開く URL を入れておいてください
(既定で GitHub Pages の公開 URL と localhost が入っています)。ここに無いオリジンからは呼べません。

### 手元で試す

Cloudflare に上げる前に、ローカルだけで動作を確認できます。

```bash
cd server
npm run db:local          # ローカル D1 にテーブルを作る
npx wrangler dev          # http://localhost:8787 で起動
```

別のターミナルでアプリを起動し (`npm run dev`)、同期サーバーの URL に
`http://localhost:8787` を入れれば、そのまま同期を試せます。

### 仕組み

サーバーは「同期コードごとに JSON をひとつ預かるだけ」です。マージはすべてクライアント側で行い、
サーバーはデータの中身を解釈しません。

- 同期コードは平文で保存せず、SHA-256 のハッシュだけを持ちます。
- 保存は楽観ロック (`If-Match`) で、他の端末が先に保存していたら 409 を返します。
  クライアントは取得しなおしてマージし、送り直します。
- 1回に保存できるデータは 1MB までです。

## 構成

```
src/
  lib/taskGenerator.ts  期間・量・曜日設定 → 日別タスク(予備日と切り上げの中核)
  lib/reschedule.ts     進捗に応じて残りを配り直す
  lib/progress.ts       連続達成記録・遅れ/貯金の集計・毎日の確認対象の抽出
  lib/amount.ts         量の丸めと、誤差を積まない合算
  lib/sync.ts           端末間のマージ (プランは新しいほう、記録は日ごとに新しいほう)
  lib/syncClient.ts     同期サーバーとのやりとり
  hooks/useSync.ts      自動同期 (起動時・変更後・オンライン復帰時)
server/
  src/index.ts          同期サーバー (Cloudflare Workers)
  migrations/           D1 のスキーマ
  lib/date.ts           'YYYY-MM-DD' 文字列ベースの日付ユーティリティ
  storage.ts            localStorage への保存・読み込み・書き出し
  hooks/usePlans.ts     プランとタスクの CRUD
  pages/                今日 / プラン一覧 / 作成・編集 / 詳細 / 設定
  components/           タスク行・進捗バー・曜日エディタ・ストリークカード
```

技術構成: React 19 / TypeScript / Vite / Tailwind CSS / Vitest。バックエンドはありません。
